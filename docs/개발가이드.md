# 개발 가이드 (팀원용)

## 사전 요구사항

- Docker Desktop (Postgres용)
- Python 3.11+ (3.13도 OK — `requirements-pipeline.txt` 설치 시 주의, 아래 [알려진 이슈](#알려진-이슈))
- Node.js 18+
- ffmpeg (전처리 검증/실행 시 필요): `brew install ffmpeg`

## 처음 1회 (clone 직후만)

```bash
# 1. Postgres
docker compose up -d postgres

# 2. Backend
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                       # GEMINI_API_KEY 등 채우기
alembic upgrade head                       # DB 테이블 생성

# 3. Frontend (현재 페이지 미작성이라 띄울 필요 없지만 미리 의존성만)
cd frontend
npm install
cp .env.local.example .env.local
```

확인:
- http://localhost:8000/health → `{"status":"ok"}`
- http://localhost:8000/docs → Swagger UI

## 초기 세팅 이후 개발 도중 📌

```bash
# Postgres가 떠있는지 확인 (대부분 자동으로 떠있음 — restart: unless-stopped 정책)
docker compose ps                          # postgres "running (healthy)" 확인

# Backend (실제로 매번 치는 건 이 줄)
cd backend && source .venv/bin/activate && uvicorn app.main:app --reload --port 8000
```

→ 사실상 `uvicorn` 한 줄. `--reload` 옵션이라 코드 저장하면 자동 재시작.

**Frontend(Next.js)는 지금은 안 띄워도 됨.** 촬영 페이지가 아직 Next.js에 없고, 검증은 백엔드가 `/dev` 경로로 서빙하는 정적 페이지(`backend/dev_static/index.html`)로 함. 슬라이스 1에서 Next.js 촬영 페이지 만들면 그때부터 `npm run dev` 필요.

## 검증용 촬영 페이지 (`/dev`) 📌

별도 server 안 띄워도 됨. **`uvicorn`이 알아서 서빙**.

`backend/app/main.py`에 다음 코드가 있어서 `DEBUG=true`일 때만 자동 mount:
```python
if settings.debug:
    app.mount("/dev", StaticFiles(directory=".../dev_static", html=True), name="dev")
```

브라우저로 열기:
```
http://localhost:8000/dev/?project=<project_id>
```

`project_id`가 **필수 쿼리스트링**. 없으면 alert 뜨고 안 시작됨.

### project_id를 어디서 얻나
미리 프로젝트를 한 번 만들어둬야 함. 한 번만 만들면 그 ID 계속 재사용 가능:

```bash
# 방법 A — Swagger UI (브라우저)
#   http://localhost:8000/docs 에서 POST /projects 시도해보기
#   body: {"title": "테스트"}
#   응답의 project_id 사용

# 방법 B — curl
curl -X POST http://localhost:8000/projects \
  -H 'Content-Type: application/json' -d '{"title":"테스트"}'

# 방법 C — 이미 만든 게 있는지 확인
curl http://localhost:8000/projects
docker compose exec postgres psql -U podium -d podium -c "SELECT project_id, title FROM projects;"
```

→ 응답에서 `project_id`(예: `1`)를 받아 URL에 박음: `/dev/?project=1`

## 전체 동작 검증 (STEP 1 + STEP 2) 📌

촬영 페이지 한 곳에서 끝까지 검증.

### 1) 프로젝트 준비
위 "project_id를 어디서 얻나" 참고. 처음이면 `POST /projects` 한 번 호출.

### 2) 촬영 + 전처리 + VLM 분석
브라우저로 http://localhost:8000/dev/?project=1 (또는 본인 project_id):

1. **Start recording** → 카메라 권한 허용 → 30초 이상 발표 시뮬레이션 → **Stop & finalize**
2. `✓ /end done. chunks=N, total_duration=Xs, status=preprocessed` 로그 뜸 → 전처리 완료
3. **Analyze motion (VLM)** 버튼이 활성화됨 → 클릭
4. "calling /analyze/motion ... (Gemini 호출, 청크당 수십초 소요)" 로그 + 분 단위 대기
5. `✓ /analyze/motion done in Xs. analyzed=N/N, status=analyzed` → VLM 완료

### 3) 결과 확인 (3가지)

```bash
# (a) 파일 시스템
ls backend/uploads/<session_id>/
#   chunks/, audio/, full_video.webm, full_audio.wav, vlm_analysis.json

# (b) DB — 세션/청크/VLM 결과 한 번에
docker compose exec postgres psql -U podium -d podium -c "
SELECT
  s.session_id, s.status,
  count(DISTINCT c.chunk_id)     AS chunks,
  count(DISTINCT ca.chunk_id)    AS analyzed_chunks
FROM sessions s
LEFT JOIN chunks c          USING(session_id)
LEFT JOIN chunk_analyses ca USING(chunk_id)
GROUP BY s.session_id
ORDER BY s.session_id;
"
# status='analyzed', chunks=analyzed_chunks 면 성공

# (c) VLM 결과 상세
docker compose exec postgres psql -U podium -d podium -c "
SELECT c.chunk_index, ca.posture, ca.eye_contact, ca.gesture, ca.gesture_counts
FROM chunks c JOIN chunk_analyses ca USING(chunk_id)
WHERE c.session_id = <session_id>
ORDER BY c.chunk_index;
"
```

### 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| `/dev/` 404 | DEBUG=false | `.env`에 `DEBUG=true` 후 uvicorn 재시작 |
| `start failed: 404 project not found` | project_id 잘못됨 | `POST /projects` 다시 만들거나 GET으로 확인 |
| `Analyze motion` 누르면 500 + `ModuleNotFoundError: google` | google-genai 미설치 | `pip install google-genai python-dotenv` |
| `Analyze motion` 누르면 500 + `GEMINI_API_KEY 환경변수가 설정되지 않았습니다` | .env 키 누락 | `backend/.env`에 `GEMINI_API_KEY=AIzaSy...` 추가 후 uvicorn 재시작 |
| `relation "chunk_analyses" does not exist` | 마이그레이션 미적용 | `alembic upgrade head` |
| 버튼 안 보임/캐시된 옛 페이지 | 브라우저 캐시 | `Cmd+Shift+R` 강제 새로고침 |

`/dev` mount(`backend/dev_static/`)는 Next.js 촬영 페이지가 생기면 제거 예정 (현재 임시).

## 코딩 컨벤션

### 백엔드
- **새 모델**: `app/models/<domain>.py` → `__init__.py` re-export → `alembic revision --autogenerate -m "..."` → 검토 → `alembic upgrade head`
- **새 라우터**: `app/api/<domain>.py`에 `APIRouter` → `app/main.py`에서 `include_router`
- **DB 세션**: `Depends(get_db)`로 주입
- **환경변수**: `app.core.config.settings` 통해 접근 (직접 `os.getenv` X)

### Git
- 브랜치: `feature/<설명>` (예: `feature/pipeline-step2-vlm`)
- 커밋 메시지: 영문 + 명령형 ("Add X", "Fix Y")
- 본문 있을 땐 "Why" 중심
- 슬라이스 끝나면 PR → 짧은 리뷰 → main 머지 (1~2일 안에)
- gitignored: `_refs/`, `_legacy/`, `backend/uploads/*` (단 `.gitkeep` 유지), `.venv/`, `node_modules/`, `.next/`, `.env`
