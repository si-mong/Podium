# 개발 가이드 (팀원용)

> 2026-11-27 기준. 로컬에서 띄우고 → 고치고 → 확인하는 데 필요한 것만 모았다.
> 결정 배경·전체 구조·진행 상황은 [CLAUDE.md](./CLAUDE.md), API 는 [Dev-API명세](./Dev-API명세.md), 흐름은 [Design-시스템흐름](./Design-시스템흐름.md).

## 사전 요구사항

- Docker Desktop (Postgres 용)
- Python 3.11 이상 (배포 이미지는 3.13)
- Node.js 18+
- ffmpeg: `brew install ffmpeg`
- API 키 (분석까지 돌릴 때): `OPENAI_API_KEY`(STEP 4·5·비교), `GEMINI_API_KEY`(STEP 2)

## 처음 1회 (clone 직후만)

```bash
# 1. Postgres (저장소 루트에서)
docker compose up -d postgres

# 2. Backend
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-pipeline.txt   # 파이프라인(PyTorch 포함)까지 — 무거움
cp .env.example .env              # OPENAI_API_KEY, GEMINI_API_KEY 채우기. DEBUG=true 그대로
alembic upgrade head              # DB 테이블 생성

# 3. Frontend
cd ../frontend
npm install
cp .env.local.example .env.local  # NEXT_PUBLIC_API_URL=http://localhost:8000
```

확인:
- http://localhost:8000/health → `{"status":"ok"}`
- http://localhost:8000/docs → Swagger UI
- http://localhost:3000 → 랜딩 페이지

### 로그인하려면

이메일 회원가입은 없앴다. 로컬에서 로그인하는 방법은 둘 중 하나:

1. **구글 로그인 (권장)** — `backend/.env` 에 `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` 를 넣는다.
   Google Cloud 콘솔의 OAuth 클라이언트에 승인된 리디렉션 URI `http://localhost:8000/auth/google/callback` 이 등록돼 있어야 한다. 키는 사용자에게 받을 것.
2. **이메일+비밀번호** — `DEBUG=true` 일 때만 열린다. 비밀번호가 있는 예전 계정·개발용 계정만 된다.

관리자 화면(`/admin`)을 보려면 로그인한 계정을 관리자로 지정:
```bash
# cwd = backend/, venv 활성화
python -m app.scripts.set_admin <내 이메일>
```

### STT 는 어디서 도나

`backend/.env` 의 `WHISPER_MODEL`:
- `hf:rearleg/SeloWhisper-ko-disfluency` (기본) — **내 컴퓨터에서** 실행 (맥은 MPS). 첫 실행 때 모델(약 3GB)을 내려받는다.
- `modal:rearleg/SeloWhisper-ko-disfluency` — Modal 서버리스 GPU 에서 실행. `MODAL_TOKEN_ID/SECRET` 필요 (배포 서버는 이 방식).

## 개발 도중 (매번) 📌

```bash
# Postgres — restart: unless-stopped 라 대부분 이미 떠 있음
docker compose ps                  # postgres "running (healthy)" 확인

# 터미널 1: Backend
cd backend && source .venv/bin/activate && uvicorn app.main:app --reload --port 8000

# 터미널 2: Frontend
cd frontend && npm run dev         # http://localhost:3000
```

`--reload` 라 백엔드 코드를 저장하면 자동 재시작, 프론트는 HMR.

## 조건부 (가끔)

| 상황 | 추가 명령 |
|---|---|
| pull 받았더니 `requirements*.txt` 변경 | `pip install -r requirements.txt -r requirements-pipeline.txt` |
| pull 받았더니 `backend/alembic/versions/` 에 새 파일 | `alembic upgrade head` |
| 모델(`app/models/`)을 내가 바꿈 | `alembic revision --autogenerate -m "<설명>"` → 파일 열어 검토 → `alembic upgrade head` → [DB-변경이력](./DB-변경이력.md)에 한 절 추가 |
| `.env` 값 수정 | uvicorn 재시작 (`Ctrl+C` → 다시) |
| frontend `package.json` 변경 | `npm install` |

## 동작 확인 📌

### 화면으로 (본 흐름)

1. http://localhost:3000 → 로그인 → (첫 로그인이면 프로필 — 건너뛰어도 됨)
2. **내 기록** → 폴더 만들기 → **발표 추가** → 촬영하거나 영상 파일 업로드
3. 분석이 단계별로 진행된다: 영상 준비 → 목소리 → 구간 나누기 → 동작 → 구간별 피드백 → 총평
   (음성 분석이 가장 오래 걸린다. 로컬 STT 면 몇 분)
4. 대시보드에서 결과 확인. 같은 폴더에 회차가 2개 이상이면 **비교 분석** 탭

### API 로 (단계별)

http://localhost:8000/docs 에서 **Authorize** 에 access 토큰을 넣고 순서대로 호출:
`/end` → `/analyze/voice` → `/analyze/segments` → `/analyze/motion-by-segment` → `/analyze/segment-feedback` → `/analyze/overall-feedback`.
선행 조건과 응답은 [Dev-API명세](./Dev-API명세.md) 1·7절.

### 결과를 직접 보기

```bash
# 파일
ls backend/uploads/<session_id>/
#   chunks/, audio/, full_video.webm, full_audio.wav, vlm_chunks/, vlm_analysis.json

# DB — 최근 세션의 상태와 구간 수
docker compose exec postgres psql -U podium -d podium -c "
SELECT s.session_id, s.project_id, s.session_no, s.status, count(g.segment_id) AS segments
FROM sessions s LEFT JOIN segments g USING (session_id)
GROUP BY s.session_id ORDER BY s.session_id DESC LIMIT 10;"

# 단계별 실행 기록 (어디서 실패했나, 몇 초 걸렸나) — 관리자 화면에서도 보임
docker compose exec postgres psql -U podium -d podium -c "
SELECT step, status, model, duration_ms, left(error, 80) AS error
FROM analysis_events WHERE session_id = <session_id> ORDER BY started_at;"
```

psql·DBeaver 사용법은 [DB-Postgres사용법](./DB-Postgres사용법.md).

### 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 로그인 버튼이 회색 / "구글로 로그인해주세요" | 구글 키 없음 | 위 "로그인하려면" 참고 |
| 프론트에서 API 호출이 CORS 에러 | 프론트 주소가 `CORS_ORIGINS` 에 없음 | `backend/.env` 의 `CORS_ORIGINS` 에 추가 후 uvicorn 재시작 |
| `relation "..." does not exist` | 마이그레이션 미적용 | `alembic upgrade head` |
| `Can't locate revision identified by '...'` | DB 는 새 스키마인데 지금 브랜치에 그 리비전 파일이 없음 (브랜치 이동) | 그 리비전이 있는 브랜치(보통 main)를 받아온다. [DB-변경이력](./DB-변경이력.md) |
| `alembic upgrade head` 가 "Multiple head revisions" | 다른 브랜치에서 리비전이 따로 생김 | `alembic heads` 확인 → `alembic merge -m "merge" <a> <b>` |
| 음성 분석 500 + `ModuleNotFoundError` (torch, transformers 등) | 파이프라인 패키지 미설치 | `pip install -r requirements-pipeline.txt` |
| 구간 분리·피드백 실패 + OpenAI 인증 에러 | `OPENAI_API_KEY` 누락 | `.env` 에 넣고 재시작 |
| 동작 분석만 실패 (나머지는 진행됨) | `GEMINI_API_KEY` 누락 또는 Gemini 일시 오류 | 키 확인. 대시보드 "다시 분석하기"는 빠진 단계만 다시 돈다 |
| 영상이 재생되다 멈춤 / 401 | 재생 티켓(30분) 만료 | 페이지 새로고침 |
| 음성 분석을 다시 돌리려는데 400 | 이미 `segmented` 상태 | `/end` 부터 순서대로 다시 호출 |

## 코딩 컨벤션

### 백엔드
- **새 모델**: `app/models/<domain>.py` → `__init__.py` re-export → `alembic revision --autogenerate` → 검토 → `alembic upgrade head` → DB-변경이력 기록
- **새 라우터**: `app/api/<domain>.py` 에 `APIRouter` → `app/main.py` 에서 `include_router`
- **인증·소유권**: `user_id: int = Depends(get_current_user_id)` 를 받아 `get_owned_project/session(db, id, user_id)` (`app/api/_deps.py`)
- **분석 라우터**: `@tracked("<step>", model=...)` 를 붙이면 실행 기록이 남는다. 무거운 파이프라인 모듈은 함수 안에서 import
- **DB 세션**: `Depends(get_db)`
- **환경변수**: `app.core.config.settings` 로 접근 (직접 `os.getenv` X)

### Git
- 브랜치: `feat/<설명>`, `fix/<설명>` (예: `feat/compare-history`, `fix/step5-headline-text`)
- 커밋 메시지: `type(scope): 한국어 설명` — 예) `feat(dashboard): 구간별 지표 탭마다 설명 추가`, `fix(step5): …`
  type 은 `feat` / `fix` / `perf` / `style` / `docs` / `chore`
- 본문 있을 땐 "Why" 중심
- 기능은 브랜치 → PR → main 머지. 문구·여백 같은 작은 수정과 문서는 main 에 바로
- 배포(EC2)는 main 기준 — 머지됐는지 확인하고 배포
- gitignored: `_refs/`, `_legacy/`, `_plans&docs/`, `backend/uploads/*`(`.gitkeep` 유지), `.venv/`, `node_modules/`, `.next/`, `.env`, `.env.local`
